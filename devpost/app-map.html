Configuration and errors stay server-side

The provider adapter reads OPENROUTER_API_KEY and OPENROUTER_MODEL (default openai/gpt-6-luna). User-safe error mapping lives in lib/generation-error.ts. Never expose the key through a NEXT_PUBLIC_ variable.

2. Reference code route

Open these three stops in order while following one submitted brief. The browser behavior can be tried locally with npm run dev; this route is not a record of a completed learner walkthrough.

Stop 1 · Form and contract

components/marketing-studio.tsx

MarketingStudio owns the brief. Start at loadSample, updateBrief, and handleSubmit to see sample loading, edits, validation, focus management and the request.

lib/marketing-schema.ts

marketingBriefSchema checks required inputs and the conditional offer. marketingResultSchema defines the result, and validateMarketingResultForBrief checks the selected platforms and ordered seven days.

Stop 2 · Server request

app/api/generate/route.ts

POST reads and validates the request, checks the generation switch, calls the adapter, and returns a safe JSON response.

lib/openrouter-marketing.ts

generateMarketingResult calls OpenRouter through the Responses API, parses with the Zod output format, handles incomplete/refusal/error cases, then applies the brief-specific checks.

Stop 3 · Results and copy

components/campaign-results.tsx

CampaignResults maps the summary, one card per platform and seven expandable campaign days to the screen.

components/copy-button.tsx

CopyButton owns each card's independent success state, resets its timer after repeated clicks, clears it on unmount, and announces feedback for assistive technology.

3. Where to start a change

To change this, start here

  • Brief fields, sample loading or validation UI: components/marketing-studio.tsx and lib/marketing-schema.ts.
  • Prompt, model or provider handling: lib/openrouter-marketing.ts.
  • Campaign result layout: components/campaign-results.tsx and app/globals.css.
  • Copy confirmation behavior: components/copy-button.tsx and components/copy-button.test.tsx.
  • Server request behavior: app/api/generate/route.ts and app/api/generate/route.test.ts.

4. A practice to reuse

Turn one acceptance criterion into one bounded change

The approved spec defines the campaign result shape; validateMarketingResultForBrief enforces exact platform matching and ordered seven-day output; tests in lib/marketing-result.test.ts check that contract. For another AI feature, start a Codex task with one observable requirement, the relevant files, and the check that proves it—then review the diff before moving on.

5. Remaining hands-on review

These checks are still to be tried in the current checkout before the final review can be marked complete.

  • Make one real OpenRouter request; check separate selected-platform captions and exactly seven ordered days.
  • Change a brief field and regenerate; verify the new campaign replaces the old one only after success.
  • Cause a failed regeneration; verify the brief and previous successful result remain available.
  • Review keyboard focus and the desktop, tablet and mobile layouts.
  • Confirm the Git status and public-safe file list before publishing.
